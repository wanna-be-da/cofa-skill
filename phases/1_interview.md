# Phase 1. 고객 인터뷰

## 목적
DM을 통해 고객의 요구사항을 체계적으로 수집한다.

## 질의서 템플릿

아래 질의서를 고객 DM으로 전달하고, 답변을 수집한다.

---

### 1. 프로젝트 개요
- Q1-1. 만들고자 하는 프로그램(서비스)은 무엇인가요? 한 문장으로 설명해 주세요.
- Q1-2. 이 프로그램이 필요한 배경이나 해결하고자 하는 문제는 무엇인가요?
- Q1-3. 이 프로그램의 최종 사용자(타겟 유저)는 누구인가요?

### 2. 핵심 기능
- Q2-1. 반드시 포함되어야 하는 핵심 기능을 우선순위 순으로 나열해 주세요.
- Q2-2. 있으면 좋지만 필수는 아닌 부가 기능이 있나요?
- Q2-3. 사용자 인증/로그인 기능이 필요한가요?

### 3. 데이터
- Q3-1. 다루어야 할 주요 데이터는 무엇인가요?
- Q3-2. 외부 API나 데이터 소스 연동이 필요한가요?

### 4. UI/UX
- Q4-1. 웹 / 모바일 / 데스크톱 중 어떤 플랫폼을 대상으로 하나요?
- Q4-2. 주요 화면(페이지) 구성을 간략히 설명해 주세요.

### 5. 기술 제약사항
- Q5-1. 지정된 기술 스택(언어, 프레임워크)이 있나요?
- Q5-2. 배포 환경에 대한 요구사항이 있나요?
- Q5-3. 성능 요구사항이 있나요?

### 6. 제출 및 평가
- Q6-1. 최종 제출물의 형태는 무엇인가요?
- Q6-2. 평가 기준이나 채점 항목이 공유되어 있나요?
- Q6-3. 인수 시 테스트 항목 또는 자체 테스트 기준이 있나요?

### 7. 기타
- Q7-1. 특별히 주의해야 할 제약 조건이나 금지 사항이 있나요?
- Q7-2. 추가로 전달하고 싶은 내용이 있나요?
- Q7-3. 프로그램 보안과 관련하여 추가적인 요구사항이 있나요?

---

## 실행 프롬프트

```
위 질의서를 고객 DM으로 전달했고, 아래는 답변 결과이다.
이를 바탕으로 interview/requests.md (요구사항 정의서)를 작성해줘.

[답변 내용을 여기에 붙여넣기]
```
